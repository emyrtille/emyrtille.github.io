## 01 / BUILDING SERVICES

### Make complex requirements *work.*

I've developed backend services in PHP and Symfony across different product contexts, including business-to-business APIs, data imports and synchronization workflows. Earlier in my career, I also worked across the stack, building Vue.js interfaces alongside backend APIs.

These experiences taught me to understand existing code, clarify requirements with teammates and deliver changes that fit into larger systems.

## 02 / EVOLVING EXISTING SYSTEMS

### Modernize with *care.*

I contributed to the redesign and modernization of high-traffic backend services, including work moving functionality from PHP to Go. My contributions combined software development, technical design and support for gradual migrations.

Working with engineers, Product and stakeholders, I helped clarify existing behavior, prepare transitions and support testing and monitoring. The teams observed improvements in performance and infrastructure efficiency; these were collective results, not outcomes I delivered alone.

## 03 / DESIGNING APIS

### Start with a *clear interface.*

I have worked on API design and implementation in different settings, from production services to early technical prototypes.

In one recent initiative, I proposed an API structure and built an initial prototype before other developers continued with specification and implementation. I enjoy making interfaces understandable and creating foundations that teams can extend.

## 04 / ENGINEERING IN PRACTICE

### Stay close to *delivery.*

I have helped bootstrap services, configure development tooling and quality checks, and integrate new code with existing infrastructure.

I also work on API testing and engineering practices, including automated checks in pull-request workflows. I value code reviews, pairing and the everyday decisions that keep a codebase healthy.

## MY APPROACH

### Curious, practical, *hands-on.*

I like understanding why a system works the way it does before proposing changes. Sometimes that means writing a prototype; sometimes it means improving an existing implementation or helping a team deliver a safer transition.

The common thread is building useful software while keeping it understandable for the people who maintain it.
