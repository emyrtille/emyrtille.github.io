## 01 / ENGINEERING WORKFLOW AUTOMATION

### Make recurring work *manageable.*

I designed a scheduled AI-assisted workflow to help my team manage dependency update pull requests.

Using information already provided by the dependency update tool, the workflow reviews updates across multiple repositories, prioritizes them against defined criteria and prepares a weekly overview for the team.

The results feed into a recurring team communication process, helping the developer responsible for the week focus on the updates that need attention.

Rather than building a complex analysis system, I focused on making better use of existing information and connecting tools to reduce repetitive coordination work.

## 02 / API TESTING & QUALITY

### Make validation *easier to start.*

I built an initial GitHub Actions workflow that generates Postman requests configured for pull request preview environments.

This first version simplifies the preparation of API tests by connecting requests to the relevant temporary environment. Test execution and automated result validation are not yet part of the workflow.

I also developed an experimental OpenAPI validator that checks API specifications for consistency, identifies potential issues and suggests corrections. I shared the working prototype with my team, although it has not been adopted as a broader standard.

Both initiatives reflect my interest in making quality checks easier to access and more consistent throughout development.

## 03 / PERSONAL AI-ASSISTED TOOLING

### Shape tools around *the way I work.*

I created a personal Claude skill to turn technical discussions into structured Jira tickets.

Rather than generating generic descriptions, the skill follows a template, writing style and level of detail that I define, helping me turn exploratory conversations into actionable work items.

I also use AI for code exploration, reviews and challenging technical ideas. I treat it as a tool for accelerating investigation and reducing repetitive work, while keeping responsibility for the final output.

## MY APPROACH

### Automate with *intention.*

I prefer starting with a useful first version, understanding its limitations and improving it as the need becomes clearer.

Not every task needs a sophisticated system. Sometimes a small workflow, a reusable tool or a well-defined interface is enough to make everyday engineering noticeably easier.
